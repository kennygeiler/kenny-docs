## 2. If he asks (true as of 9129f7d)

1. **"Did a model produce that number?"** No. `core/engine.py` runs `rules_ratified.json`; tonight every model touchpoint is off (`KENNY_LLM=off`, badge says so; `params.source: stub` = regex intent parse). With a key, Claude only classifies, parses and ranks, through one schema-validated chokepoint that falls back on any slip.
2. **"Who wrote the five live rules?"** Four were written by me in July 2026 against the clause text (approvals back-filled into the ledger and labelled back-filled). The fifth, longevity, was written **today by a coding agent in my Claude Code session** straight into the rule file; its approver field reads "not yet human-ratified" and I have not pushed it through the gate. No model draft has ever been approved (the local record: model drafts failed their known-answer check). README still says "four live rules" — stale.
3. **"What stops a wrong rule going live?"** `POST /admin/ratify`: approver name required; a rule must fire in a known answer and every known answer must still reproduce; a 99x rule for a unit with no known answer gets `Nothing was approved — no known answer exercises …`; every refusal is an `authoring.blocked` ledger event. Blind spots are visible: try-to-break survivors.
4. **"Is this deployed?"** No. `kenny-production.up.railway.app` runs the pre-today build. Today's work is merged on `demo-2026-10-07` locally and on GitHub; the Railway volume (roster, case.yaml, rules) needs a reseed; the header doesn't show the running commit yet.
5. **"How many corpora / customers?"** One corpus (Central Fire District of Santa Cruz County: 4 MOUs + salary schedule), one district, zero users. `core/` is case-agnostic and `cases/` is a swappable bundle, but it has never run against a second corpus.
6. **"How does the OCR check work?"** MOUs are scans → OCRmyPDF/Tesseract text layer → docling clauses with bboxes; the catalog records `text_origin` per page. p.22 cells were re-read by RapidOCR at 3x into `cell_checks.json` (precomputed, no engine at runtime). Not done: the ratify gate isn't wired to disputed cells yet, and Chief Officers p.26's grid is docling noise (93 disputed cells) — honest, not pretty.
7. **"Can the ledger be forged?"** Locally it's hash-chained but unsigned ("Integrity-only"); a shared deploy requires `KENNY_LEDGER_KEY` (HMAC) kept off the data volume. Rechaining is caught by the recorded head only; there is no external anchoring. `/healthz` verifies the chain on every probe.
8. **"What can the skeptic do?"** Budget 12 tool calls (4 searches, 6 page reads, 6 engine runs, 8 warnings), all via `scripts/skeptic.py` and recorded before the agent sees results; it quotes pages or reports engine outputs, never arithmetic. `start` exits if an API key is in the environment — produced on subscription, zero API spend; the app imports the artifact once and serves it.
9. **"What's replay actually proving?"** Schema-2 snapshot freezes subjects, params, full rule text, roster/rule-file/source-PDF/engine hashes, write-once, bound to `answer.snapshot` by hash. Not done: entitlement answers don't snapshot; no Replay button in the drawer (URL only).
10. **"What happens when the model misbehaves?"** 30 s timeout, one retry, circuit breaker, pydantic-validated replies, global handler returns `mode: blocked` instead of a 500, badge turns "degraded". Also: admin is unauthenticated locally (auth deliberately not touched today); rounding policy is stated in `case.yaml` (extension rounded once; 656.82, not 656.88; district practice unconfirmed).
